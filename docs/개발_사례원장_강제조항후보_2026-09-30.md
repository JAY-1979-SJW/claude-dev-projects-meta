# 강제 조항 후보 — 사례 원장에서 규칙(rules.toml)으로 승격할 만한 것

**상태:** 제안. `standard/rules.toml` 에는 **넣지 않았다.** 조항을 추가하면 모든 프로젝트의 hook 과 `audit-kit std` 결과가 바뀌므로
아래 "승격 전 확인"을 마치고 사용자가 승인한 것만 옮긴다. 근거 사례는 `개발_사례원장_2026-09-30.md` 의 CASE 번호.

**분류**
- **자동화 가능:** 코드·설정만 보고 기계적으로 검사할 수 있다 → `rules.toml` 조항 후보
- **골격에 심기:** 검사보다 새 프로젝트 골격에 처음부터 파일로 넣는 편이 효과적 → `audit-kit new` / `templates/`
- **절차:** 사람이나 AI 의 작업 방식 → `CLAUDE.md` / 체크리스트

## 1. 골격에 심기 (검사보다 확실함, 우선 권장)

| 후보 | 근거 | 내용 | 승격 전 확인 |
|---|---|---|---|
| **G1. 상태 격리 conftest** | CASE-12, 13c | 새 Python 프로젝트의 `tests/conftest.py` 에 "상태 파일·설정·레거시 경로를 임시 경로로 돌리는 autouse 픽스처" 뼈대를 포함. 프로젝트의 상태 경로 상수 목록만 채우면 됨 | 경로 상수가 프로젝트마다 달라 **목록 채우는 방식**을 설계해야 함 |
| **G2. CI 워크플로 초안** | CASE-02, 03, 04, 06 | `windows-latest`/`ubuntu-latest` 호스팅 러너, `permissions: contents: read`, `concurrency`, 시크릿 스캔 잡, 깨끗한 환경에서 `requirements.txt` 설치 후 테스트 | 프로젝트 유형별(서버/CLI/데스크톱) 잡 구성 |
| **G3. 브랜치 보호 스크립트** | CASE-04 | 저장소 생성 직후 `gh api` 로 필수 검사·강제 푸시 금지 설정하는 스크립트 | 저장소 소유자 권한 필요 |
| **G4. 브라우저 연결 헬퍼** | CASE-23 | 브라우저 자동화 유형(`desktop`/`mcp`)의 골격에 "프로세스당 연결 하나 + 재연결" 헬퍼를 포함 | 유형별 |
| **G5. 자격증명 저장 모듈** | CASE-14, 15, 15b | 비밀번호를 다루는 프로젝트에 OS 자격 증명 저장소 기반 모듈(fail-closed, 마이그레이션 검증) 포함 | `haehan_common` 으로 올릴지 결정 |
| **G6. 새 프로젝트 첫날 체크리스트** | 착수 체크리스트 | `templates/NEW_PROJECT_CHECKLIST.md` 로 포함하고 `/new-project` 가 출력 | 없음(문서) |

## 2. 자동화 가능 — rules.toml 조항 후보

| 후보 ID(가안) | 제목 | 근거 | 검사 방법 | 승격 전 확인 |
|---|---|---|---|---|
| **DEP-01** | `requirements.txt` 없이 import 되는 서드파티 패키지 금지 | CASE-06 | AST 로 import 한 최상위 패키지를 수집해 `requirements`/`pyproject` 와 대조 | 표준 라이브러리·로컬 패키지·동의어(예: `yaml`=`pyyaml`) 목록 필요, 오탐률 측정 |
| **DEP-02** | 사용하는 라이브러리 API 의 최소 버전이 명시 버전 이상인지 | CASE-07 | 어려움(API 별 도입 버전 DB 필요) | **자동화가 현실적이지 않음** — 절차로 두는 것을 권장 |
| **STRUCT-01** | 같은 이름의 모듈(`x.py`)과 패키지(`x/`)가 공존하면 안 됨 | CASE-16 | 파일 시스템 검사(같은 부모에 `x.py` 와 `x/__init__.py`) | 매우 단순·오탐 적음 → **가장 유력** |
| **STRUCT-02** | 분할 전후 공개 이름이 유지되는지 | CASE-08 | 분할 커밋의 `__all__`/공개 이름 diff | 분할 커밋 식별 방법 |
| **TEST-01** | 테스트가 실제 사용자 데이터 경로를 쓰지 않음 | CASE-12, 13c | conftest 에 격리 픽스처가 있는지 + 상태 파일 상수 목록과 대조 | 상태 경로 식별 방법 |
| **TEST-02** | 수집 오류가 나는 "잠금 테스트"가 skip 으로 숨지 않음 | CASE-22 | pytest 수집 오류 0 강제(이미 verify_change 에 일부 있음) | 기존 검사와 중복 여부 |
| **TEST-03** | 스크립트(`if __name__ == "__main__"`)는 서브프로세스 실행 시험이 있어야 함 | CASE-26 | 스크립트 파일 목록 vs 서브프로세스 시험 존재 | 대상이 넓어 오탐 가능 |
| **SEC-05** | 평문 비밀번호 파일 저장 금지(`open(...,'w')` 로 password 를 쓰는 패턴) | CASE-15 | 정규식 + 변수명 휴리스틱 | 기존 SEC-02 와 겹침 — 확장 여부 |
| **SEC-06** | 암호화 키 파일을 암호문과 같은 디렉터리에 두지 않음 | CASE-14 | `Fernet.generate_key` 후 파일 저장 패턴 | 정밀도 |
| **CI-01** | 공개 저장소에서 `runs-on: self-hosted` 금지 | CASE-03 | 워크플로 파싱 + 저장소 공개 여부 | 공개 여부를 알아내는 방법 |
| **CI-02** | 워크플로의 임시 우회 설정은 되돌릴 조건을 주석으로 가져야 함 | CASE-02 | `self-hosted`/`continue-on-error` 근처 주석 검사 | 형식 정의 |
| **SUP-01** | 경고 억제 주석(`nosec`)은 도구가 보고하는 줄에 있어야 함 | CASE-18 | 커밋 후 도구를 다시 실행해 억제가 적용됐는지 확인 | 도구별 지목 규칙 |
| **CFG-01** | 설정 파일 주석에 도구가 찾는 키 이름(`[tool.ruff` 등)을 쓰지 않음 | CASE-32 | `pyproject.toml` 의 주석 줄 안에 `[tool.` 검사 | 단순 → 유력 |
| **GEN-01** | 자동 생성 파일에 충돌 표식이 남으면 안 됨 | CASE-21 | `<<<<<<<`, `>>>>>>>` 검사(이미 커밋 체크리스트가 함) | 이미 있음 — 확장 불필요 |
| **WEB-01** | 브라우저 자동화 코드에서 호출마다 새 연결(`connect_over_cdp`)을 맺지 않음 | CASE-23 | AST 로 도구 함수 안의 `connect_over_cdp` 호출 검사(테스트로 이미 구현) | 프로젝트별 예외 |

**우선 승격을 권장하는 세 가지**(구현이 단순하고 오탐이 적으며 근거가 분명): **STRUCT-01**(모듈·패키지 이름 충돌), **CFG-01**(설정 주석의 키 이름), **WEB-01**(브라우저 새 연결).
나머지는 오탐률을 실제 코드에서 측정한 뒤 판단한다.

## 3. 절차 (CLAUDE.md / 체크리스트로)

| 후보 | 근거 | 내용 |
|---|---|---|
| **P1** 깨끗한 환경 확인 | CASE-06 | 의존성을 바꾼 작업은 새 가상환경에서 테스트한다 |
| **P2** 실제 실행 검증 | CASE-26, 27 | 합성 데이터 통과를 "동작한다"로 보고하지 않는다. 스크립트는 직접 실행, 화면 자동화는 실제 화면 1회 |
| **P3** 변이 시험 | CASE-27 | 규칙·안전 로직을 새로 만들면 일부러 코드를 망가뜨려 테스트가 잡는지 확인 |
| **P4** 실제 데이터를 건드리는 검증 금지 | CASE-13 | 격리 검증은 복사본에서. 정리 명령의 대상 경로를 실행 전 출력 |
| **P5** 서브에이전트 보고 검증 | CASE-48 | 재사용/삭제 판단은 직접 열어 확인 |
| **P6** 점수가 이상하게 움직이면 측정부터 의심 | CASE-32 | 개선 작업 뒤 점수가 내려가면 코드가 아니라 측정 방식을 먼저 본다 |
| **P7** 통계는 표에서 계산 | 이 원장 초안 자체 | 손으로 센 요약은 틀린다. 스크립트로 계산 |
| **P8** 생성 파일 충돌은 정본 도구로 | CASE-21 | 손 병합 금지 |
