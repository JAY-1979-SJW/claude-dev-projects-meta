## 2. 전체 구조: 3중 방어

```
 [1. 예방]                 [2. 즉시 검사]                  [3. 완료 검사]
 코드 작성 전               Edit/Write 직후                  응답 종료 직전
 ─────────────             ──────────────────              ──────────────────
 CLAUDE.md 규칙            PostToolUse hook                 Stop hook
 dup-checker 에이전트       py_post_edit.py                  py_stop_check.py
 haehan_common 공용 lib     ruff --fix → format              pylint 중복 검사
                           치명 오류 → exit 2 (되돌림)        pytest
                           mypy (새 파일)                    문제 → exit 2 (1회)
                                     └──── /py-check : 수동 전체 검사 ────┘
```

| 단계 | 구성 요소 | 파일 위치 | 막는 것 |
|---|---|---|---|
| 예방 | 공통 규칙 | `03. PYTHON\CLAUDE.md` | 복사, 백업 파일, 인코딩 누락, print 남용 |
| 예방 | 중복 검색 에이전트 | `~\.claude\agents\dup-checker.md` | 이미 있는 함수를 새로 만드는 것 |
| 예방 | 공용 라이브러리 | `03. PYTHON\00_공용라이브러리` | 프로젝트 간 코드 복사 |
| 즉시 | 저장 후 검사 hook | `~\.claude\hooks\py_post_edit.py` | 문법 오류, 미사용 import, 함수 재정의, encoding 누락, 타입 오류 |
| 완료 | 종료 전 검사 hook | `~\.claude\hooks\py_stop_check.py` | 새 중복 코드, 테스트 실패 |
| 수동 | 전체 검사 skill | `~\.claude\skills\py-check\SKILL.md` | 전체 규칙 위반, 포맷, 기존 중복 |
| 공통 | 린트 규칙 | `03. PYTHON\ruff.toml` | (모든 단계에서 사용) |
| 신규 | 프로젝트 템플릿 | `03. PYTHON\templates\` | 새 프로젝트가 규칙 없이 시작하는 것 |

### 2.1 설정 위치를 이렇게 나눈 이유
- **Claude Code 설정(hook, agent, skill)은 사용자 레벨(`~\.claude`)** 에 둔다. 하위 프로젝트는 각각 따로 Claude Code를 열기 때문에, `03. PYTHON\.claude\settings.json`에 두면 하위 프로젝트 세션에는 적용되지 않는다. 대신 hook 스크립트가 첫 단계에서 대상 파일이 `03. PYTHON` 밖에 있으면 아무것도 하지 않고 끝나므로, 다른 작업에는 영향이 없다.
- **CLAUDE.md는 `03. PYTHON`에** 둔다. Claude Code는 작업 폴더에서 상위 폴더로 올라가며 CLAUDE.md를 모두 읽으므로, 하위 프로젝트 어디서 열어도 적용된다. 프로젝트별 CLAUDE.md는 그대로 두고 함께 적용된다.
- **ruff 설정은 `03. PYTHON\ruff.toml`에** 둔다. ruff도 상위 폴더로 올라가며 설정을 찾는다. 단, 프로젝트에 `[tool.ruff]`가 있는 `pyproject.toml`이 있으면 그 설정이 우선하므로, 거기에 `extend = "../ruff.toml"`을 추가한다(예: `14. CAD 산출 프로그램`).

## 3. 구성 요소 상세

### 3.1 CLAUDE.md (공통 규칙)
Claude Code 공식 권장에 따라 200줄 이내로 짧게 유지하고, 코드에서 알 수 없는 것만 적는다. 핵심은 다음과 같다.
1. 새 함수나 파일을 만들기 전에 기존 구현을 검색한다(현재 프로젝트 → haehan_common → 다른 프로젝트).
2. 다른 프로젝트 코드를 복사하지 않고 공용 라이브러리로 옮긴다.
3. 백업 파일이나 폴더를 만들지 않고 git으로 관리한다.
4. Windows와 한글: encoding을 지정하고, pathlib을 쓰고, `py -m pip`로 설치한다.
5. 품질: 타입 힌트, logging, 구체적인 예외 처리, `with`로 리소스 정리.
6. 흐름: 탐색 → 계획 → 작성 → 검증(`/py-check`).

### 3.2 PostToolUse hook: `py_post_edit.py`
- **실행 시점**: Claude가 Edit, Write, MultiEdit로 파일을 저장한 직후.
- **처리 순서**
  1. 대상 판별: `.py` 파일이고, `03. PYTHON` 안에 있고, 백업·venv 폴더가 아니어야 한다. 조건에 맞지 않으면 exit 0으로 끝낸다.
  2. 수정 파일 목록을 세션별로 기록한다(`%TEMP%\claude_py_hooks\<session>.txt`). Stop hook이 이 목록을 사용한다.
  3. `ruff check --fix`: 전체 규칙 중 자동으로 고칠 수 있는 것을 고친다(미사용 import 삭제, import 정렬, 최신 문법 등).
  4. `ruff format`으로 코드 모양을 통일한다.
  5. 치명 규칙만 다시 검사하고, 남은 오류가 있으면 **exit 2**로 끝낸다. 이때 stderr 내용이 Claude에게 전달되어 즉시 수정하게 된다.
  6. 새 파일(git에서 아직 추적하지 않는 파일)이면 mypy로 타입을 검사한다.
- **치명 규칙 (작업을 막는 규칙)**

  | 규칙 | 의미 |
  |---|---|
  | E9 | 문법 오류 |
  | F | pyflakes: 정의되지 않은 이름, 미사용 import·변수, 함수 재정의(F811) |
  | B | bugbear: 가변 기본 인자 같은 흔한 버그 |
  | PLE | pylint 오류급 |
  | PLW1514 | `open()` 등에 encoding 누락 (한글 깨짐 방지) |
  | BLE001 | `except Exception` 남용 |

- **나머지 규칙은 자동 수정만 하고 막지 않는다.** 기존 코드는 규칙을 어긴 곳이 많아서, 모두 막으면 한 줄 고칠 때마다 관련 없는 코드까지 고쳐야 하기 때문이다. 전체 규칙 검사는 `/py-check`로 한다.
- **조정**: 환경 변수 `CLAUDE_PY_MYPY=off|new|all`로 mypy 범위를 바꾼다. 기본값은 new다.
- 각 도구의 실행 시간은 30초로 제한한다. ruff가 설치되어 있지 않으면 설치 방법만 안내하고 막지 않는다.

### 3.3 Stop hook: `py_stop_check.py`
- **실행 시점**: Claude가 응답을 마치려고 할 때.
- **처리 순서**
  1. `stop_hook_active`가 true면 바로 끝낸다. 이미 한 번 되돌린 상태이므로, 이렇게 해서 무한 반복을 막는다.
  2. 이번 세션에 수정된 .py 파일 목록을 읽는다. 없으면 끝낸다. 목록은 읽은 뒤 비운다.
  3. 파일이 속한 프로젝트(`03. PYTHON` 바로 아래 폴더)마다 다음을 실행한다.
     - `pylint --enable=duplicate-code`(R0801): 6줄 이상 같은 코드를 찾는다. 주석, docstring, import, 함수 시그니처는 비교에서 제외한다. **이번에 수정한 파일이 관련된 중복만** 보고하고, 기존에 있던 중복은 무시한다.
     - `tests\` 폴더가 있으면 `pytest -x -q`를 실행한다. 프로젝트에 `.venv`나 `venv`가 있으면 그 파이썬을 쓴다. **테스트 실패(exit 1)일 때만** 막고, 모듈이 없는 것 같은 환경 문제로는 막지 않는다.
  4. 문제가 있으면 공식 Stop hook 응답 `{"decision": "block", "reason": "..."}`을 출력한다. reason이 Claude에게 전달되어 고친 뒤 마무리하게 된다. 안내 문구에는 실제로 발견된 문제 유형(중복, 테스트 실패)만 넣는다.
     - 화면에는 "Stop hook error"로 표시되지만, 작업을 막을 때 Claude Code가 원래 그렇게 표시하는 것이고 정상 동작이다.
- 중복 검사는 최대 120초, 테스트는 최대 150초, hook 전체는 300초로 제한한다.

### 3.4 dup-checker 서브에이전트
- 읽기 전용이다(Read, Grep, Glob만 사용). 빠르고 저렴한 haiku 모델을 쓴다.
- "만들려는 기능"을 설명하면 공용 라이브러리 → 현재 프로젝트 → 다른 프로젝트 순서로 비슷한 함수를 찾는다. 결과로 **재사용 / 확장해서 재사용 / 새로 작성** 중 하나를 권한다.
- CLAUDE.md 1장에서 "새 모듈을 만들기 전에 호출"하도록 지시해 두었다. 직접 부를 수도 있다: "dup-checker로 엑셀 읽기 기능 있는지 찾아줘"
- `03. PYTHON\.ignore`: Claude의 검색 도구(ripgrep)가 venv, site-packages, 백업 폴더를 건너뛰게 한다. 이 파일이 없으면 중복을 검색할 때 라이브러리 코드가 섞인다.

### 3.4.1 검사 명령 자동 허용
`~\.claude\settings.json`의 `permissions.allow`에 `py -3.14 -m ruff|mypy|pylint|pytest`를 Bash와 PowerShell 양쪽으로 등록했다. 그래서 Claude가 검사를 돌릴 때 권한 확인에 걸리지 않는다. 명령을 `;`로 묶으면 여전히 확인이 뜨므로, CLAUDE.md와 skill에 "하나씩 실행" 규칙을 넣었다.

### 3.5 /py-check skill
검사 순서: ruff 전체 규칙 → 포맷 확인 → mypy → pylint 중복 → pytest. 결과는 표로 요약한다. 이번 작업에서 생긴 문제는 고치고, 기존 문제는 보고만 한다. 필요하면 내장 명령 `/simplify`(코드 정리)나 `/code-review`(버그 검토)로 이어간다.

### 3.6 ruff.toml (공통 린트 규칙)
- `target-version = "py311"`: 기존 3.11 venv와 호환되게 한다. 새 프로젝트는 템플릿에서 py314로 올린다.
- `preview = true`: PLW1514를 쓰려면 필요하다.
- 중복·죽은 코드와 관련된 규칙: F401(미사용 import), F811(재정의), F841(미사용 변수), ERA001(주석 처리된 코드), ARG(미사용 인자), SIM(중복 분기), PIE.
- 복잡도 제한: C901 10, 인자 6개, 분기 12개, return 6개, 문장 50개.
- 백업, venv, build, dist 폴더는 검사하지 않는다.
- 한글 전각 문자 오탐(RUF001~003)과 매직 넘버(PLR2004)는 끈다.
- ruff 0.16부터는 예외 주석을 `# noqa: X` 대신 `# ruff: ignore[규칙명]`으로 쓴다(`ruff check --fix`가 자동 변환한다).

### 3.7 공용 라이브러리 haehan_common

### 3.9 추측 방지 (요구사항·라이브러리 사용법)
자동 검사는 "문법은 맞지만 원하는 동작이 아닌 코드"를 잡지 못한다. 이 빈틈은 규칙, 문서 조회, 승인 절차로 줄인다.

| 추측 유형 | 대책 | 위치 |
|---|---|---|
| 요구사항 추측 | 모호하면 코드를 쓰기 전에 질문하고 추천안을 제시한다. 요청하지 않은 기능은 추가하지 않는다 | CLAUDE.md 0장 |
| 큰 변경을 임의로 진행 | 파일 3개 이상, 동작·형식 변경, 새 패키지 설치는 계획을 먼저 보여주고 승인을 받는다 | CLAUDE.md 5장 |
| 라이브러리 API 추측 | Context7 → 공식 문서 WebFetch → 설치된 소스 순서로 확인한다. AutoCAD COM은 Autodesk 문서와 기존 동작 코드를 기준으로 한다 | CLAUDE.md 0장, settings.json |
| "동작한다"는 거짓 보고 | 완료 보고에 "실행해서 확인함", "문서로 확인함", "확인 못 함(가정)"을 구분해 적는다 | CLAUDE.md 0장 |
| 원하는 결과가 모호함 | 새 기능은 테스트(입력 → 기대 결과)를 먼저 작성해서 방향을 고정한다 | CLAUDE.md 5장 |

**문서 연동 구성**
- **Context7 MCP** (원격 HTTP, 사용자 범위): openpyxl, pywin32 등 라이브러리 문서를 검색한다. 무료 요금제는 월 1,000회다. 조회할 때 권한 확인이 뜨지 않도록 `mcp__context7`을 허용했다.
  - 등록 명령(키는 사용자가 직접 입력):
    `claude mcp add --scope user --header "Authorization: Bearer <키>" --transport http context7 https://mcp.context7.com/mcp`
- **WebFetch 허용 도메인**: docs.python.org, peps.python.org, openpyxl.readthedocs.io, mhammond.github.io, help.autodesk.com, fastapi.tiangolo.com, pandas.pydata.org, requests.readthedocs.io, docs.astral.sh, docs.pytest.org, code.claude.com. WebSearch도 허용했다.

**등록부에 없는 도구 (AI 조사 강제, 2026-09-27)**: 새 import 가 표준 라이브러리·프로젝트 내부 모듈·등록부 어디에도 없으면 저장을 거부하고, Claude 에게 ① 공식 개발자 센터를 찾아 WebFetch 로 열고 ② 문서에서 확인한 주의점만 정리해 ③ `~/.claude/docs_registry.local.toml` 에 항목을 추가한 뒤 ④ 다시 저장하게 한다. 로컬 등록부는 install 이 덮어쓰지 않으며, 항목은 `verified = "AI 추가, 사람 확인 전"` 으로 표시되어 사람이 검토한 뒤 `standard/docs_registry.toml` 로 승격한다. **역할 분담**: 공식 사이트를 찾고 읽고 이해하는 것은 AI, 조회했는지 확인하고 거부하는 것은 스크립트(hook), 사람은 AI 가 추가한 항목이 진짜 공식 사이트인지 확인한다.

**한계**: hook 은 문서를 열었는지까지만 확인하고 읽고 이해했는지는 확인하지 못한다. AI 가 잘못된 사이트를 공식으로 등록할 수 있어 사람의 검토가 필요하다. WebFetch 만 인정하므로 오프라인·폐쇄망에서는 문서를 열 수 없어 `CLAUDE_PY_DOCS=warn` 으로 낮춰야 한다. AutoCAD·Excel·pywin32 문서는 개요 페이지까지만 열어 확인했다.

### 3.12 실행 증거 강제 (ERR-04, 2026-09-27)
"실행하지 않고 동작한다고 보고"하는 것을 Stop hook 이 직접 검증해서 막는다. AI 가 한 말이 아니라 **실제 도구 호출 기록과 hook 이 직접 재현한 결과**로 판정한다. (공식 best-practices: "a Stop hook runs your check as a script and blocks the turn from ending until it passes")

| 증거 | 누가 | 내용 | 강도 |
|---|---|---|---|
| T1 테스트 + 수정 줄 커버리지 | hook 이 직접 | 프로젝트 `tests/` 를 coverage 와 함께 실행해 **수정한 함수 본문 줄**의 50% 이상이 실행됐는지 확인. 최상위 줄은 import 만으로 "실행됨"이라 제외 | 강 |
| T3 AI 실행 성공 기록 | PostToolUse 기록 | 마지막 수정 뒤 AI 가 실행한 `pytest`·`python 파일`·`python -m 패키지`·`python -c` 의 성공. `cd 프로젝트 && …`·`Push-Location`·`B=python; $B -m pytest` 를 따라간다 | 보조 |
| T2 import 스모크 | hook 이 직접 | **AST 안전 판정을 통과한 모듈만** 자식 프로세스에서 import. "import 가능함"일 뿐 수정 코드의 동작은 미검증 | 약 |

- **실측으로 확인한 hook 입력**: 성공은 `PostToolUse`(종료 코드 필드 없음), 실패는 별도 이벤트 `PostToolUseFailure`(`error` = "Exit code N"), 백그라운드는 결과 없음(증거 불인정). transcript 는 비동기로 기록돼 판정에 쓰지 않는다.
- **판정**: 파일별로 마지막 수정 이후 T1 > T3 > T2 순으로 찾고, 없으면 차단(면제 없음). AI 의 마지막 실행이 실패면 import 가 되어도 통과시키지 않는다. **1회 차단 후 통과**(`stop_hook_active`). 모드 `CLAUDE_PY_EVIDENCE` = block | warn | off.
- **안전 정책** (hook 이 프로젝트 코드를 실행하므로): 모듈 최상위에 호출·삭제·네트워크가 있으면 **실행하지 않는다**(프로젝트 안에서 import 하는 모듈까지 따라감, 알려진 안전 호출만 허용, 모르는 객체의 메서드는 불허). 자식 프로세스 + 타임아웃(테스트 120초·import 30초), 초과 시 **프로세스 트리째 종료**(Windows `taskkill /T /F`). 토큰·비밀번호 환경변수 제외. 산출물은 임시 폴더. 네이티브 Windows 에는 OS 샌드박스가 없어 **실수 방지용**이지 악성 코드 방어가 아니다.
- **종료 코드를 가린 실패**: `pytest | tail`, `; echo $?` 처럼 종료 코드가 0 이 돼도 출력에 `N failed`·`FAILED`·`Traceback`·`exit=4` 가 있으면 실패로 기록한다.
- **테스트 품질(ERR-05, 참고 등급)**: 템플릿에 `filterwarnings=["error"]`, `--strict-markers`, `pytest-timeout` 추가, `audit-kit std` 가 프로젝트 설정을 검사. 변이 테스트는 mutmut 이 네이티브 Windows 에서 안 되어 Stop hook 에서 제외(GitHub Actions 리눅스 러너 단계로 분리 예정).

| 검증 (2026-09-27) | 결과 |
|---|---|
| 안전 시험 41개 | 부작용 모듈은 실행되지 않아 파일이 남음, 무한 루프 모듈은 시작하지 않음, 타임아웃 뒤 **손자 프로세스까지 종료**, 비밀 환경변수 미전달, 산출물 없음 ✅ |

### 3.13 위험 명령 차단 (SEC-01, 2026-09-27)
`C:\dev\PYTHON` 이 통째로 지워졌던 사고를 막기 위한 PreToolUse hook(`py_danger_guard.py`, matcher `Bash|PowerShell`).

| 판정 | 대상 |
|---|---|
| **deny** | 재귀 삭제·`robocopy /MIR`·포맷이 **보호 경로**(드라이브 루트, 홈, Windows·Program Files, `C:\dev`, OneDrive, 검사 범위 폴더, `.git`, 설정한 `protected_paths`) 또는 파이프로 받은 대상을 겨눔 |
| **ask** | 그 밖의 재귀 삭제, 대상이 변수라 확인할 수 없음, `git reset --hard`·`clean -fd`·`push --force`·`branch -D`, `iex`·`-EncodedCommand`·`irm \| iex`, `python -c`·heredoc·`node -e` 안의 삭제 API, .NET 삭제 |
| 통과 | 그 밖의 명령, 캐시·임시 폴더(`__pycache__`, `node_modules`, `%TEMP%`) 삭제, heredoc 로 파일에 쓰는 **데이터** |

- **파싱**: 따옴표 밖 연결자로 분리, 백틱·따옴표·경로 접두어(`/bin/rm`)·래퍼(`sudo`·`env`·`timeout`)·`git -C` 정규화, `bash -c`·`cmd /c`·`powershell -Command`·`$( )` 안쪽 재귀 분석, `cd` 와 변수 대입(`DIR=…; rm -rf $DIR`)을 따라감, heredoc 본문은 받는 명령에 따라 데이터/코드로 구분.
- **내부 오류는 ask**: hook 이 크래시하면 exit 1 이라 차단되지 않으므로 명시적으로 확인을 요청한다.
- **검증**: 시험 310개(우회 표기 200여 종, 적대 입력 25종의 종료 시간 제한 포함) + **과거 명령 1,107건 재생**(통과 96%, ask 4%, deny 2건 = 실제 사고 명령) + 실제 세션에서 Bash·PowerShell 양쪽의 보호 경로 삭제가 실행 전 차단되는 것을 확인.
- **검증 중 발견한 결함**: 끝나지 않은 heredoc 에서 **무한 루프**(메모리 6GB 사용 후 정지) — 설치 전에 시험이 잡았고, 검색 위치를 항상 앞으로 보내고 횟수를 제한해 고쳤으며 적대 입력 시험을 정식으로 추가했다. 또한 `` 역참조가 제어 문자로 저장되는 편집 오류, `-Force`(PowerShell)를 `-f`(bash) 묶음 옵션으로 오인한 결함도 시험이 잡았다.
- **한계**: 명령 텍스트 검사는 **보안 경계가 아니다**(공식 문서도 동일). 파일에 써 둔 스크립트(`.ps1`·`.bat`·`.py`) 안의 삭제와 인터프리터 내부 동적 삭제는 막지 못한다.
- **모드**: `CLAUDE_PY_DANGER` = block(기본) | ask(deny 도 확인으로 낮춤) | off.

### 3.16 API 실재 검증 (ERR-02, 2026-09-27)
`py_api_guard.py`(PreToolUse `Write|Edit|MultiEdit`, `.py`). mypy 의 `attr-defined` 은 `py.typed`·stub 이 없는 패키지를 `Any` 로 봐 환각을 놓치므로, 이를 보완하는 실시간 hook 이다.

- **방식**: Edit/MultiEdit 는 조각이라 옛 파일에 그대로 적용해 재구성한 전체 텍스트로 AST 를 만든다. `import`/`from import` 별칭을 모듈 경로로 풀고, `별칭.a.b...` 체인에서 앞부분이 실제 서브모듈(파일·폴더 존재)인 동안 계속 따라가다가 **정확히 하나** 남으면 그 모듈의 소스를 **직접 읽어**(import 안 함) 최상위 정의를 확인한다. 표준 라이브러리는 부작용이 없다고 알려져 있어 이 hook 프로세스에서 바로 import 해 진짜 `__file__` 을 쓴다(`os.path` 처럼 `sys.modules` 를 직접 조작한 별칭도 이렇게 해야 찾는다). 외부 패키지는 프로젝트 venv 의 site-packages 를 파일로만 뒤진다.
- **범위 밖(통과, "미검증")**: 인스턴스 메서드(`wb.active.cell`), `__getattr__`, `from x import *`, 컴파일된 확장(.pyd/.so), 네임스페이스 패키지, venv 를 못 찾음, 프로젝트 내부 모듈. 표준 라이브러리 중 내부에서 `from x import *`(스타 임포트)를 쓰는 모듈(`os`, `os.path`, `shutil`, `sqlite3`, `http.client`, `xml.etree.ElementTree`, `datetime`, `asyncio` 등, 표본 19개 중 약 1/3)은 dynamic=True 로 판정되어 사실상 검증 대상에서 빠진다 — 오탐 방지를 위한 의도된 설계의 결과이며 새 버그 아님(2026-09-28 실측 확인).
- **검증 중 발견한 정밀도 결함**: 모듈 최상위 이름을 `tree.body` 직계만 보면 `if`/`try` 블록 안의 정의를 놓친다 — `os.py` 가 `if 'nt' in _names: from nt import *` 로 플랫폼별 함수를 넣는 게 대표 사례라, `os.startfile`·`os.getcwd` 를 실제로 있는데 "없다"고 오탐했다. `hashlib.py` 의 `globals()[name] = ...`(동적 생성), `re.py` 의 `@enum.global_enum` 데코레이터(클래스 멤버를 모듈에도 노출)도 같은 이유로 오탐했다. 이 세 가지를 각각 고쳤다(제어문 재귀, `globals()` 조작 감지, `global_enum` 데코레이터 특별 처리) — **설치 전 실제 코드 측정이 잡은 결함**.
- **검증**: 표준 라이브러리 사용 25,604건(4,612개 파일) + venv 갖춘 프로젝트(견적 프로그램·중복코드 분석기·audit-kit 등) 2,023건에서 **오탐 0건**. 재현율은 시험(json.dump_s·존재하지 않는 속성 등)으로 확인.
- **결정**: 오탐 0건을 확인해 기본을 곧바로 **block** 으로 뒀다(다른 규칙처럼 warn 으로 시작하지 않음). `CLAUDE_PY_API` = block(기본) | warn | off.
- **한계**: 정적 분석이라 동적 속성 부여는 못 본다. 클래스·인스턴스 메서드는 애초에 범위 밖이라 mypy/pyright 몫이다.

### 3.17 GitHub Actions 변이 테스트 (audit-kit, 2026-09-27)
DUP-02(중복) 같은 규칙은 "위반이 없다"가 "시험이 실제로 그 코드를 검증한다"를 뜻하지 않는다. 변이 테스트(mutmut)로 시험이 코드를 실제로 잡아내는지 잰다. audit-kit 저장소에만 먼저 넣었다.

- **왜 GitHub Actions 뿐인가**: `mutmut`(v3.8.0, 2026-09-27 설치해 직접 확인)는 **네이티브 Windows 를 아예 거부**한다 — 어떤 하위 명령을 줘도 "please use the WSL"(github.com/boxed/mutmut issue #397) 만 찍고 종료해, `--help` 조차 실행 안 된다. 이 PC 에서는 그래서 검증할 수 없고, Actions 의 `ubuntu-latest` 가 유일한 실행 환경이다.
- **바뀐 함수만 검사**: 전체(약 7,000줄)를 매번 돌리면 무료 실행 시간(월 2,000분, private)을 넘긴다. `scripts/changed_functions.py` 가 `git diff -U0` 로 바뀐 줄을 찾고, AST 로 그 줄을 담은 함수의 점 표기 이름(`모듈.함수`, 중첩이면 `모듈.클래스.메서드`)을 뽑아 `mutmut run "*모듈.함수*"` 에 넘긴다. 함수 밖(모듈 최상위) 변경은 놓친다는 한계가 있다.
- **`[tool.mutmut]` 키는 mutmut 3.x 소스(configuration.py)로 직접 확인**했다: `source_paths`(구 이름 `paths_to_mutate` 는 폐기 경고), `also_copy`(README 예시엔 없었지만 코드에 실재 — `std/data`·`templates`·`scripts`(실행 실패로 발견, 아래) 처럼 사본에도 있어야 하는 것들), `pytest_add_cli_args_test_selection`.
- **CI 판정은 mutmut 가 대신 안 해 준다**: `mutmut run` 자체는 변이체가 다 살아남아도(전부 시험을 통과해도) 그냥 exit 0 로 끝난다(소스 확인: `__main__.py` 의 `run()`/`_run()` 이 생존 개수로 `exit()`를 부르지 않는다). 그래서 `mutmut export-cicd-stats` 가 만드는 `mutants/mutmut-cicd-stats.json`(killed/survived/total 등, 이 명령의 소스 코드 주석에 "CI/CD 파이프라인에서 병합을 막는 데 쓰라"고 적혀 있다)을 `scripts/summarize_mutation.py` 로 읽어 `$GITHUB_STEP_SUMMARY` 에 사람이 읽을 표로 남긴다. **첫 실행 결과를 보기 전까지는 점수로 빌드를 실패시키지 않는다**(판정 기준은 실측 후 정한다).
- **워크플로**: `.github/workflows/ci.yml`(push/PR 마다 pytest + `audit-kit std` 자기 검사, Python 3.11 필수 + 3.14 는 `continue-on-error`로 지원 여부만 관찰), `.github/workflows/mutation.yml`(`workflow_dispatch` 로 직접 대상 지정 가능 + 매주 월요일, 7일 전 커밋과 비교). 둘 다 `permissions: contents: read`, `concurrency` 로 중복 실행 취소, 액션은 SHA 로 고정(checkout `3d3c42e5…` v7.0.1, setup-python `5fda3b95…` v7.0.0, upload-artifact `043fb46d…` v7.0.1, 2026-09-27 GitHub API 로 재확인).

**실제 GitHub Actions 실행으로 확정한 것(2026-09-27, run 36303475978~36304758746, 총 6회 실행)**
1. **`ci.yml`**: pytest·std 자기 검사 모두 Python 3.11·3.14 에서 정상 동작(3.14 도 setup-python 이 실제로 지원함을 확인, `continue-on-error` 는 안전망으로만 남김). 이 저장소에 이번 작업과 무관한 기존 치명 위반 11건이 있어 `--fail-on critical` 을 걸면 항상 빨간불이 뜨는 것을 확인 → 그 부채를 정리하기 전까지 `--fail-on never` 로 낮춤.
2. **버그 1 — `also_copy` 에 `scripts/` 누락**: 첫 mutmut 실행이 `mutants/` 사본에서 `tests/test_changed_functions.py` 의 파일 경로 임포트(`scripts/changed_functions.py`)를 못 찾아 기준(clean) 테스트 자체가 깨졌다. `also_copy` 에 `"scripts"` 를 추가해 고쳤다.
3. **버그 2 — 변이체 이름 형식이 문서·예상과 다름**: README 예시(`mutmut run "my_module.my_function*"`)를 그대로 믿고 `"모듈.함수*"` 를 줬더니 `AssertionError: Filtered for specific mutants, but nothing matches`. 실제 이름은 `mutmut results --all true` 로 직접 찍어 확인했다 — `모듈.x__함수__mutmut_N`(mutmut 이 함수 이름 앞에 `x__` 를 붙인다, 소스 어디에도 문서화돼 있지 않음). 접두어를 예측하지 않도록 패턴을 `"*모듈.함수*"` 로 양쪽에 와일드카드를 둬 고쳤다.
4. **버그 3 — 변이 점수 계산이 틀림**: `export-cicd-stats` 의 `total` 은 이번 실행이 아니라 **그 파일에 지금까지 쌓인 전체 변이체 수**다(예: `rule_by_id*` 로 4개만 검사해도 `total` 은 그 파일 전체인 123). `killed / total` 로 계산하면 75% 짜리 결과가 2.4%로 잘못 나온다. `killed / (killed + survived)` 로 고쳤다.
5. **실측 성능**: `rules.py`(90줄) 전체 변이(123개) 생성에 약 48초, 함수 하나로 좁히면(4개 검사) 실행 전체가 약 1분. 바뀐 파일이 없으면(예: 문서만 수정) `changed_functions.py` 가 빈 목록을 내고 mutmut 자체를 건너뛰어 21초 만에 끝난다 — "바뀐 함수만" 전략이 실제로 시간을 아낀다.
6. **`gh` 인증**: `git push` 에는 `repo` 권한만으론 부족하고 `workflow` 스코프가 추가로 필요했다(`.github/workflows/*.yml` 을 포함한 push 는 GitHub 가 별도로 막는다) — `gh auth refresh -h github.com -s workflow` 로 추가.
- **사용자 조치로 확인한 것(2026-09-27)**: `gh auth status` 로그인됨(이후 `workflow` 스코프 추가), 원격 `JAY-1979-SJW/audit-kit`(private) 실재, Actions 켜져 있음(`allowed_actions: all`). **push 완료**(커밋 최신 `871811a`), `ci.yml`·`mutation.yml` 모두 실제로 초록불 확인.

## 5. 운영 절차

### 5.1 평소 작업
1. 하위 프로젝트 폴더에서 Claude Code를 연다. CLAUDE.md와 hook은 자동으로 적용된다.
2. 여러 파일에 걸친 작업이면 plan mode(Shift+Tab)로 계획부터 세운다.
3. 저장할 때마다 hook이 검사한다. 오류가 되돌아오면 Claude가 스스로 고친다.
4. 마칠 때 Stop hook이 중복과 테스트를 검사한다.
5. 큰 작업을 마친 뒤에는 `/py-check`를 실행한다.

### 5.2 hook 확인과 문제 해결
- Claude Code에서 `/hooks`를 실행해 PostToolUse와 Stop hook이 등록되어 있는지 확인한다.
- hook을 잠시 끄려면 `~\.claude\settings.json`의 `hooks` 항목을 지우거나, 해당 세션에서 `/hooks`로 끈다.
- mypy가 번거로우면 `CLAUDE_PY_MYPY=off`로 설정한다.
- **OneDrive가 꺼져 있으면** 클라우드 전용 파일을 읽지 못해 ruff와 pylint가 실패할 수 있다. 작업 전에 OneDrive를 켜 둔다. 자주 쓰는 프로젝트 폴더는 "이 장치에 항상 유지"로 설정하는 것을 권장한다.
